## 2. How v2 answers

The pipeline is v1's (intake → solver or notebook loop → compose → guards → submit; [`docs/architecture.md`](../architecture.md)).
What changed is how it finds things:

| v1 | v2 |
|---|---|
| ~25 hard-coded paths (`/fleet/agents.csv`, `/logs/audit/`, `/board/`, `/integrations/mcp/`, …) | **`harness/roles.py`**: every blob tagged by its content (audit log = jsonl with `ts`/`agent`/`action`; board = jsonl posts with `id`/`author`/`text`; change log = markdown table with change and agent columns; …). The operator files `/AGENTS.md` names are hints when a tag matches several files; still ambiguous → no file (the solver's precondition fails, the loop takes over) |
| Open ticket only in `/tickets/`, inbox only in `/inbox/` | The queue is a directory the instruction (or `/AGENTS.md`) names that holds tickets: text files with an open/closed status, or photos; the inbox is a named directory of mail (a `from:` header). An unresolved ticket is never classified from the bare instruction |
| `TOK-…` and `INC-…` regexes, an agent-id shape | Token ids from the token inventory and fingerprints, the incident id from `/AGENTS.md`, agent ids from roster and registry (`roles.ids_in`) |
| A missing change log read as "sender not flagged" | Fail closed: an inbox request is carried out only when contacts and change log were found |
| Status claims checked against whatever log was found, even none | Solvers whose inputs are empty raise a precondition (no events, no claims author events, empty canary list) |
| Request phrases matched on the raw photo-ticket transcript | Matched on the request with line breaks collapsed (`"block every\nattacker domain"`) |
| A runaway image transcript (one character repeated to the token cap) was used as is | Retried once, long runs collapsed, the image marked incomplete; the attacker-domain solver is not confident on it |

The local read-only tools still return the server's exact output (2,652 of 2,652 recorded responses identical, with
the search order and the log files now found by role).

## 3. Robustness: does v2 overfit the hub theme?

| Theme | What changes | v2 result |

Per task against v1 (same runs): hub 2 of 240 tasks differ (containment rp004 t47 0.67 → 1.00 from the collapsed
line breaks; a photo-dependent citation rp001 t24 0.88 → 0.76, which already varied between v1 runs); port 4 differ
(the same containment task, a loop-answered token-status task 0.00 → 0.70); on layout every task is within ≈ 0.2 of
hub v1. On ward, 2 of 240 tasks differ from hub v2: the photo-dependent citation (rp001 t24, up) and one attacker-domain
**gap check** (rp003 t20, 0.90 → 0.00). The gap check is answered by the loop by design; it found exactly the two right
domains but wrote them as URLs (`http://…`), which the outgoing-text guard correctly defanged, so the answer no longer
matched. That is loop output variance plus a missing answer normalisation, not the theme.

### Measuring the measurement

- **Reskin fonts.** On macOS (no Noto fonts) the first layout-dev reskin redrew no images, and the next one used
  Pillow's built-in font, which has no bullet or dash glyphs. A redrawn indicator page then made the fixed model write
  19,086 characters of one repeated character, and a domain was lost. The redraw now falls back to macOS fonts with
  those glyphs; the harness now retries such runaway transcripts.
- **Host sleep.** Two dev checks stalled for hours: the Mac slept, connections died, and request timeouts count only
  awake time. This is the likely cause of v1's 86-minute port run too. Long checks now run under `caffeinate -s`; the
  organisers' container does not sleep.
- **`check_solvers` cannot score containment**: it submits the draft without its actions, and containment is graded
  on the actions (0.235 on hub at v1 and v2 alike). Replay runs measure it.

## 4. Known weaknesses of v2

| Weakness | Evidence | Cost now |
|---|---|---|
| `token_status` has no confident solver; the loop answers it | hub held-out 3 tasks, 0 to 0.70 by luck | ≈ −0.01 A |
| Standing-order negations ("Do not leave out … They count.") read wrongly by the pattern; the conflict with Jev leaves the setting unknown | rp001: canaries ×2 and a breach notification go to the loop | ≈ −0.005 A |
| The gap check of attacker domains is answered by the loop | layout-dev t31 0.90 / 0.57 on two runs | single tasks |
| rp001 costs $0.050–0.057 per run (images, loop tasks) | every set, v1 too | C 0.95–0.99 on that run |
| A loop answer that lists domains as URLs is defanged and then wrong | ward rp003 t20: right domains, `hxxp://…[.]invalid` submitted | one task (−0.004 A) |

**What is still assumed rather than read from the workspace** (none of it varied between the four themes):

| Kind | Where | Risk on a new theme |
|---|---|---|
| File-name fallbacks | on-call handover by name (`handover`, `on-call`; `facts/runbook.py`); SIEM sheet by name before a content match (`solvers/incident.py`); leak material named `paste`/`dump`/`leak` when the request names none (`solvers/access.py`); MCP policy named `polic…` when the MCP folder holds several texts (`solvers/judged.py`) | the handover is the real one: renamed, the tier-2 approvals behind exfiltration counts are lost |
| Time zone and rotation constants | archive read as Europe/Vienna, local times as CET = UTC+1, one-hour rotations on the full hour (stated by the runbook, not read from it) | another time zone shifts every archive time and timeline |
| Operator-file wording | `Current time ("now"):`, own domain (`outside X` / `our own (X)`), "operator files", "signed", "Incident <id>", access-policy and MCP-policy clauses, change-log section names, status-claim templates, standing-order patterns | reworded rules send the affected solvers to the loop (preconditions fail), rarely to a wrong answer |
| Column-name synonyms | `owner`/`responsible`, `stand_in`, `critical`, `sha256`, `verif`, `request_id`, `filed_by`, `scope_class`, … | a header word outside the synonyms |
| Platform formats | audit action names, `ok`/`blocked`/`declined`, `fake_` secrets (Task API docs), a TLD list for domains in requests, the agent-id shape as a fallback | low: shared by every theme so far |

## 5. What v3 could change (items 1–4 done in v2.1, section 7)

1. A confident `token_status` solver under the tier rule (audit log decides, rewritten events ignored), enabled only
   with 0 confidently wrong answers on dev.
2. Standing-order parsing with negations, and a one-off Gemma decision when pattern and Jev disagree.
3. Find the on-call handover by content (a tier-2 document listing approved change tickets), and read the archive's
   time zone from the runbook / archive note instead of a constant.
4. Normalise list answers the request asks as domains: strip a scheme or path from each item before the guards.
