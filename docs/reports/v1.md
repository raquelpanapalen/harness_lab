# Status report v1: `v1-hub-baseline`

Snapshot of the harness at tag `v1-hub-baseline` (commit `4d0793f`, 2026-11-21): what it scores, how it gets there,
how it holds up on workspaces it was not built on, and what v2 should fix. The harness code itself is unchanged
since `6b09b7d` (2026-11-18); the commits since then add the theme reskin tooling under `harvester/synth/` and
make the replay server path-agnostic. A v2 report will follow the same structure so the two compare line by line.

## 2. How v1 answers

Full description: [`HARNESS.md`](../../HARNESS.md); decisions: `wayfinder/harness/SPEC.md`.

Each task is a state machine: **intake** (one Jev call picks the family, kind and allowed actions) → **solve** (a
code solver over a per-run fact layer, if the family is recognised and its preconditions hold) or the **Gemma
notebook loop** → **compose** → deterministic **guards** → **submit**, with a fallback that always submits something
of the right shape. Images are transcribed by Gemma once per run, only when a task needs them.

## 3. Robustness: does v1 overfit the hub theme?

All 44 harvested runs share one theme, `hub` (MuggingFace, an open model hub). The organisers said the final keeps
the task types under a different theme "to punish overfitting". `harvester/synth/` rewrites harvested runs into
another theme with the answers still known: every file format (text, JSON, office XML, PDF text, images by
transcript and redraw), paths, requests, expected answers and sources, with line numbers, token fingerprints and
recorded file hashes kept consistent (`check.py` verifies each run). See [`harvester/synth/README.md`](../../harvester/synth/README.md).

| Theme | What changes | v1 result |
|---|---|---|
| **port** | ~460 vocabulary swaps: organisation, attacker, domains and look-alikes, agent ids and names, people, services, token codes, artifacts, MCP servers, customers. Layout and id formats kept. | **0.962** at $0.031 vs hub 0.965: only 2 of 240 tasks score differently (one citation, one containment task that also varies between hub runs) |
| **layout** | port + 13 renamed directories (`/fleet`→`/crew`, `/tickets`→`/queue`, `/board`→`/channel`, `/logs/audit`→`/logs/gateway`…), 20 renamed files (`agents.csv`→`roster.csv`, `runbook.md`→`playbook.md`…), `TOK-`→`CRED-`, `INC-`→`CASE-`. `/AGENTS.md`, `/drafts/` kept (fixed by the Task API docs). | **0.258 at $0.17** on run 1 (stopped there: the pattern was clear and each run cost 6× normal) |

**Vocabulary is not the problem.** The harness has almost no theme words in its code (only a `vault` keyword in
one alert filter and "model card, dataset card" as examples in the judge prompt).

**Layout is.** On renamed files v1 collapses:

- intake looks for the open ticket only in `/tickets/`, so with `/queue/` the ticket is never found
  (answers like "The ticket in /queue/ is not provided");
- solvers locate their inputs by hard-coded path (~25 places: `/fleet/agents.csv`, `/fleet/tokens.csv`,
  `/fleet/token_fingerprints.csv`, `/fleet/registry_export.json`, `/fleet/changes.md`, `/board/*.jsonl`,
  `/logs/audit/`, `/logs/archive/`, `/logs/access/`, `/integrations/mcp/`, `/plans/`, `/artifacts/`, `/security/`,
  `/runbook.md`, `/standing_order.md`, `/contacts.csv`), so their preconditions fail and the tasks fall to the
  expensive loop, which returns null, empty or wrong answers;
- id regexes assume `TOK-…` and `INC-…` (`harness/wave4.py`, `harness/inbox.py`), so `CRED-…` tokens are missed and
  first-token answers come back as `"[secret removed]"`;
- status-report claims are parsed with exact template sentences (`harness/solvers/wave5.py:262-280`).

Within hub the generator already varies column names, file formats (csv / xlsx / ods, docx / odt / md, photo vs text
tickets) and file-name suffixes, and v1 handles all of that. Whether the final also renames directories is unknown;
if it does, v1 would score far below its hub numbers.

### Data bugs found while building the reskin (fixed, not harness issues)

The first port measurement (Score 0.918) overstated the gap. Two causes were in the generated data:

1. the image renderer wrapped lines at hyphens, splitting ids and paths (`survey-` / `mirror.test`) on redrawn
   tickets: containment blocked the wrong domain and draft paths were truncated;
2. rewritten MCP manifests kept their old approved SHA-256 in `approved.csv`, so the harness (correctly) disabled
   almost every server.

## 4. Known weaknesses of v1

| Weakness | Evidence | Cost now |
|---|---|---|
| Hard-coded paths and id formats | layout run 1: 0.258, $0.17 | none on hub; severe if the final renames files |
| `token_status` has no solver; the loop answers it wrong | 3/3 hub held-out tasks at 0 | −0.06 A over 5 runs |
| Gemma loop is weak where it is used | 14 loop tasks average 0.646 vs 0.986 for solvers | most of the remaining hub loss |
| Citations on L3 | L3 sources 0.87 (canaries 4/14, status claims, notify) | ≈ −0.02 A |
| A model call without a timeout can stall a run | port v1 run 3 took 86 min instead of ~4 (the 30-min final limit would cut it) | risk of unsubmitted tasks in the final |

## 5. What v2 should change

1. **Find files by role and content, not by name**: roster = the CSV whose rows hold agent ids and owners; board =
   the JSONL of posts with ids and authors; tickets = files with a `status:` line or an OPEN/CLOSED stamp, wherever
   they sit; inventories, registry, change log, plans, audit logs (JSONL with `ts/agent/action`) and the rotated
   archive likewise; `AGENTS.md` and the runbook name the operator files, so read those names from there.
2. **Learn id formats from the workspace**: token ids from the inventory, the incident id from `AGENTS.md`, instead
   of `TOK-` / `INC-` literals.
3. **Bound every model call** with a timeout so no task can stall the run.
4. Optionally: a `token_status` solver; looser status-claim parsing.

Measure v2 on all three: hub held-out (no regression from 0.965), port, and layout (all 5 runs), at ≤ $0.05 per run.

## 6. Reproduce

```bash
git checkout v1-hub-baseline
# hub held-out
uv run harvester/replay/server.py --only-runs 5 --port 3997 &
ARENA_BASE_URL=http://localhost:3997 ARENA_API_KEY=arena_local uv run main.py --kind dev --note "v1 hub"
# themes (build once; image transcripts cost ≈ $0.07 for 5 runs, cached afterwards)
uv run --with pillow harvester/synth/reskin.py --theme port --last 5
uv run harvester/synth/check.py port
harvester/synth/measure.sh port "v1 port"
python3 harvester/synth/compare.py port        # per-task differences vs hub
```
